# Pi Zero Master Monitor 📡

A lightweight, headless monitoring stack designed for the Raspberry Pi Zero. It monitors local system health (temperature, RAM, under-voltage) and sweeps the local network to ensure critical devices are online. 

Alerts and daily reports are delivered via the Gmail API using OAuth2, preventing email spam by utilizing a state-tracking flag file.

## 📂 File Directory

### Core Scripts
* `pi_monitor.py` - The master watchdog script. Runs via cron. Checks hardware health, pings network devices, writes to the log, and sends emails.
* `generate_devices.py` - A utility script that uses `nmap` to scan the local subnet and automatically generate the `devices.json` file.

### Configuration Files
* `settings.json` - The master configuration file. Contains email recipient lists, temperature thresholds, and logging preferences.
* `devices.json` - A key-value list of friendly names and IP addresses for the network ping sweep. (Can be hand-edited or generated by `generate_devices.py`).

### Authentication & State (Auto-Generated)
* `credentials.json` - Your downloaded Google Cloud Desktop OAuth client secrets (Requires manual download from Google Cloud Console).
* `token.json` - Generated automatically upon first authentication. Stores the refresh token for headless email sending.
* `alert_sent.bin` - A temporary flag file created when an alert is sent. Prevents the script from spamming your inbox while the issue is actively occurring.
* `pi_monitor.log` - The rotating log file. Tracks script execution, errors, and system status history.

## ⚙️ Initial Setup Guide

### 1. System Requirements
You will need a few system packages installed before configuring Python:
sudo apt update
sudo apt install -y python3-venv nmap

### 2. Python Virtual Environment
Create and activate an isolated Python environment to avoid package conflicts:
cd ~/gmail_test
python3 -m venv env
source env/bin/activate

Install the required Python libraries:
pip install psutil google-api-python-client google-auth-httplib2 google-auth-oauthlib

### 3. Google API Authentication
1. Place your Google Cloud `credentials.json` file in the project folder.
2. Run the master script manually for the first time. It will output a URL.
3. Copy/paste the URL into a web browser, log in to Google, and authorize the app.
4. This will generate the `token.json` file, allowing the script to run headless forever.

## 🛠️ Configuration

### `settings.json`
Edit this file to change where emails go and what triggers an alert.
* `email_config`: Add recipients to "to_list", "cc_list", etc.
* `thresholds`: Adjust "temp_alert" (default 75.0) and "temp_recovery" (default 70.0).
* `logging_config`: Adjust "level" ("INFO" or "DEBUG"), max file size, and backup retention.

### `devices.json`
To build your network watch-list automatically, run:
sudo env/bin/python generate_devices.py

(Note: sudo is required to capture MAC addresses via ARP).
After generation, open `devices.json` and manually rename the "Unknown" devices to friendly names (e.g., "Main Router").

## ⏱️ Automation (Crontab)

To run the script entirely in the background, add these entries to your crontab (`crontab -e`). 
Because we specify the exact path to the virtual environment's Python, we do not need to activate the environment first.

# 1. Run the watchdog every 5 minutes (Silent unless there is an alert/recovery)
*/5 * * * * /home/codar/gmail_test/env/bin/python /home/codar/gmail_test/pi_monitor.py

# 2. Send a guaranteed full health report every morning at 8:00 AM
0 8 * * * /home/codar/gmail_test/env/bin/python /home/codar/gmail_test/pi_monitor.py --daily

## 🩺 Troubleshooting & Logs

If emails stop arriving or devices report false-offline:
1. Check the logs: `cat ~/gmail_test/pi_monitor.log`
2. Watch real-time executions: `tail -f ~/gmail_test/pi_monitor.log`
3. Force a manual run: `~/gmail_test/env/bin/python ~/gmail_test/pi_monitor.py --daily`
4. Test an alert: Temporarily lower the "temp_alert" threshold in `settings.json` to 30.0 to trigger a fake overheat warning.
